# Domain docs

## Layout

Single-context:
- GLOSSARY.md at the repository root
- docs/adr/ for architecture decision records

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being explored.
If these files are absent, proceed silently. Domain modeling
creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note
the gap for domain modeling.

## ADR conflicts

Explicitly flag proposals that contradict an existing ADR,
identify the ADR, and explain why reopening it is warranted.
